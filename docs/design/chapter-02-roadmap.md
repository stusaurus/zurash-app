# ズラッシュ！ 第2章（第51〜100ステージ）先行開発設計

状態：**制作方針・独立研究試遊版**。第1章の正式50面・星50個・家修復15項目・承認素材71点・既存セーブは変更しない。正式キャンペーンへの組込みや追加章の発売は未承認。

## コンセプト

第1章「トリケンの家」を終えると、初めての道具を使って氷の町から外へ進む。
基本操作は継続：**壁を動かす → 滑る → 止まったマスの星を取る**。

- 第1章で10／20／30面から使える3道具は、以後「強い近道」ではなく**使わないと解けない謎**にもする。
- ただ手数を水増ししない。最短解とSランクは、正式なゲームエンジンの完全BFSによる証明を前提とする。
- 毎回アイテムを使うと作業になりうるため、使わない戦略面と混ぜる。
- 50面を過ぎてから新ギミックを追加する。基本ルールを壊さないよう、`solo-v2`に**分離して実装・検証**するまで第1章へ混ぜない。
- 特別なCPU対戦を通じ、「ズラッシュ！ ボードゲーム」のルールを示唆する。ただしCPU対戦はパズルのソロルールとは別の既存2人対戦エンジンを使う。

実装上の **51–53面は、正式な章番号を示す配置案**であって既存キャンペーンへの登録ではない。現在の試作品はアイス8手・グローブ12手・ワープ6手と短く、**機構証明用**。これを本番の51面以降として無審査採用しない。

## アイテム必須性の証明

`src/puzzle/item-necessity.js` の `verifyItemRequirement(stage,item)` は、当該アイテムの準備操作を禁止し、合法な全状態を幅優先探索する。

- `required`：アイテムを使わずに到達できる全ての状態を調べ尽くした（＝使わないとクリア不可能）。
- `optional`：当該アイテムなしのクリア手順が見つかった。
- `unverified`：時間・ノード上限に到達。**必須とは称しない。**

加えて正規のBFS `solve` でアイテムを使う合法な最短解を求め、その手順で星が全取得できることを再生する。合格のための手数制限だけで「必須」にしない。

## CPU対戦の位置付け

試遊版：`duel-boss.html`、既存 `src/engine.js` と `src/ai.js` に完全依存（研究用でのゲームルール再発明禁止）。初期盤面は既存の「はじまりの氷原」、人間先攻、CPUは「ふつう」、先に星3個で勝利。

対戦版ではグローブやワープ等のソロ専用アイテムを使わない。**ボードゲームと互換の核ルール**（壁移動＋滑走＋星取得）を印象づける。将来の販売やボードゲーム化は別プロジェクトで判断し、アプリ内対戦の独立結果をボドゲのバランス証明に流用しない。

## 運用と品質ゲート

1. 正式50面と修復・セーブを保護し、新章の試作品は`/data/chapters/chapter-02/`と別の試遊URLだけで公開。
2. アイテム・新ギミックは探索状態を完全にシリアライズし、無限ループ／死に手／戻る／再開をテスト。
3. ひとつの面で最短手数の証明、星の途中取得、不要な壁の連続移動、ヒントの段階表示を確認。
4. 最短解があっても、試遊者が「面白い」「達成感がある」と感じなければ不採用。Sランクは手数で決め、ゲーム外でのヒント利用は記録できないことを明示。
5. CPU対戦は合法手、相互手番、得点判定、先攻差、対局時間、スマホでの操作性を検証。公平性の統計が整うまで正式なボス難易度にしない。
6. 第2章を本番キャンペーンと統合する際は、**章単位のセーブキー・星報酬・解放条件・初回終了演出**を新規に設計し、第1章の互換性を回帰テストする。

研究版とアプリ版の役割を明確に分ける。現在のアプリ研究用Draft PR #7を本番mainに無断マージしない。
