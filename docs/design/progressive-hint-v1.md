# 長編パズル｜段階的ヒント v1

対象: Draft PR #7、独立試遊版 `/long-lab.html`（氷の回廊／星をめぐる迷宮／氷壁のバトン）。正式50面には影響なし。

## なぜ作るか

2026-11-01 の「氷壁のバトン」人間試遊で、ユーザーは「16手むずい！ 面白い わからない」と報告した後、チャットで最初の5手のヒントを受け、**残りを自分で考えて最短16手Sランク**を実機達成した。最初から全部の解答を見せず、詰まったところだけ解放できる仕組みを試す。

## UIの段階（選んだ面ごとに最初は全て閉じる）

| 解放段階 | 表示 | ネタバレ |
|---|---|---|
| 1. 考え方 | 壁を使った停止位置・発想の方向 | 少 |
| 2. 最初の目標 | 最初に星を取る最短手数と座標 | 中 |
| 3. 出発の手順 | 初期配置から最初の星までの具体的な合法手 | 高 |
| 4. 答え | 全部の星を取る完全な最短手順 | 全 |

ヒント3から4へ進むボタンは `最短解を見る 4/4` と明示し、誤操作で全解を見せない。開いたヒントはゲーム中だけ表示し、切り替え／再挑戦でリセットする。ヒントを使ってもS/A/Bの評価は**手数のみ**で決定する（結果にヒント回数を別記）。チャット等ゲーム外で得たヒントは計測対象ではない。

## 一貫性と安全

- 手順は `stage.proof` を `applyPuzzle` で逐次再生して組み立てる。座標、滑走方向、壁の移動元・移動先、星取得も**実際の遷移後状態**から計算。
- `stage.challenge.minimumTurns === stage.proof.length` の前提を検査。完全BFSによる最短性の証明は `tests/chapter-long-candidates.test.js` と `scripts/challenge-certify.js` で担保する。
- 盤面中の別解・寄り道を選んだ後に、初期位置の最短手順をそのまま適用できるとは限らない。ヒント3・4には「初期配置から」「最初からで確認」を明記。
- `src/puzzle/progressive-hints.js` は文字列生成のみ、端末保存やネットワーク通信を行わない。ランク判定、家修復、星報酬に変更なし。
- iPhoneではヒント表示後にパネルへスクロールし、回答一覧は高さ制限つき縦スクロール。低減モーション設定にも対応。
- クリア後のUndoで再挑戦するとプレイ時間計測を再開し、画面遷移中のアニメーションでは別ステージに切り替えない。
