# 1人用パズル検証仕様 solo-v1

この仕様はアプリ版の研究用であり、正式採用済みのゲーム仕様ではない。2人戦エンジン、CPU、既存画面には接続しない。

## 共有する基本ルール

- 盤面の幅・高さは各2〜16。`board.playableCells`で穴や変形を表す。省略時は全マス有効。
- コマは1個。上下左右へ、障害物または盤端の手前まで滑る。途中停止しない。
- 星は停止したマスにある場合だけ取得。通過では取れない。全取得でクリア。
- 各手は「準備を1回まで→滑走を1回」。壁を動かさない手も合法。
- 通常の壁移動は任意の可動壁1個を上下左右へ1マス。コマ、星、壁、固定障害物、設置済み氷、ポータル、盤外には移動できない。
- 既存の`step`と`slide`を呼び出し、座標・穴・停止位置の計算を共有する。
- 2人戦の相手の存在・交互手番・先取点・相手の閉じ込め判定は1人戦には持ち込まない。自分の移動可能性は維持する。
- 手数制限・時間制限・途中の星取得・途中ワープ・ランダム効果は追加しない。

## アイテムの検証用効果

|種類|solo-v1での効果|状態に含むもの|
|---|---|---|
|アイスブロック|指定ソケット1か所に永久固定の氷を設置。以後、滑走の停止に使える|設置済みマス・残数|
|パワーグローブ|壁1個を直線に2マス移動。中間マスも通常の移動先条件を満たす必要がある|残数|
|ワープクリスタル|ポータル上で、対のポータルへ移動。その後、必ず1回滑る|ポータル対・残数|

上記の使用はその手の壁移動の代わり。複数アイテムの同時使用、設置と壁移動の併用は不可。ワープ先での星取得は発生しない。残数0なら使用できない。ポータルは自動転送しない。

ソケットは探索の分岐数を制御する検証仕様であり、任意マスへの氷設置を実証したものではない。グローブは追加手番ではない。これらの効果を製品で確定するには試遊を要する。

## ステージと状態の分離

```js
{
  schemaVersion: 1, rulesVersion: 'solo-v1',
  id: 'pz-000001', revision: 1, status: 'candidate',
  board: {width: 4, height: 4},
  start: 0, walls: [7], stars: [2], fixed: [],
  iceSockets: [], portals: [],
  inventory: {iceBlock: 0, powerGlove: 0, warpCrystal: 0},
  goal: {type: 'collect-all'}
}
```

盤面・初期配置は不変。プレイ状態は`position/walls/stars/ice/inventory/ply`に分離する。移動中の見た目、CPU、街の施設は探索状態に含めない。

通常の壁・固定障害物・アイテム・通行マスクを区別する。壁と星の重なり、無効マス、重複、未対応のバージョン・アイテムを検査する。小さい変形盤面では、機能に必要なマスを予約してから固定障害物を置く。

新効果を追加するときは、初期配置検証、準備候補、状態遷移、状態キー、攻略再生、手作業で答えを決めたテストを一緒に変更する。既存の意味を変えるときは`rulesVersion`を上げ、旧ステージを旧仕様で再生できるようにする。現実装はsolo-v1だけを受理し、未対応バージョンを推測して実行しない。任意のプラグインや全種類の将来ギミックを自動的に処理できるわけではない。

## 探索と証明の境界

全合法手の幅優先探索。候補手の上位抽出や評価関数による枝刈りはしない。壁の配列順に依存しない局面キーで同一状態の再訪を避ける。すべての手のコストが1であるため、得られた解はこの仕様における最短手数。

- `solved`: 初期配置からの合法な手順を保存し、`applyPuzzle`を使って再生・全星取得を確認。
- `unsolvable`: 到達可能な全状態の探索が完了し、解がない。
- `budget`: 状態数または時間の上限で探索を中断。解なしとは判定しない。

生成器、探索器、再生器で移動ルールを共有する。したがって再生は「別実装の数学的証明」ではない。停止位置・星の通過・壁の違法移動・各アイテム効果・不可能例は、答えを手で決めた単体テストでも確認する。

タイマーは各探索展開の開始時に確認するため、1回分の合法手生成の間は上限を超える余地がある。現在は小盤面向けの研究器。製品上での探索はWorker化、キャンセル、メモリ上限などが必要。本実装はプレイヤー端末で大量生成する構成ではない。

## 配信・進行

100面ずつのJSONとSHA-256付きマニフェスト。読み込み時にハッシュ、件数、配置、IDの対応を検査する。3チャンクのLRUキャッシュと同時取得の共有、取得失敗時の再試行に対応。候補の読込は明示的な研究オプションを必要とする。

`id`は採用後に固定し、配置変更時は`revision`を上げる。カタログの各チャンクは任意の`ids`配列で表示順と恒久IDを別々に管理できる。第1章はこの索引を使用する。旧研究カタログは`ids`を省略した連番IDの互換形式のまま再生できる。

`completePuzzle`がクリア手順を再生してから報酬を記録する。1ステージにつき星1個を一度だけ獲得。再挑戦・再起動・改訂版のクリアで増殖しない。街の施設IDごとの支出を記録し、重複支出を防ぐ。残高はクリア報酬合計−建築支出で算出する。改訂版の最短記録はリセットするが報酬取得履歴は保つ。

従来のセーブキーは`zurash-app:puzzle-progress:v1`。第1章の試遊では明示的なプレビューモードに限り候補の進行を記録し、`zurash-app:chapter-preview:ice-town:v1`へ隔離する。本番用・2人戦とは分離する。解放時期は10/20/30面で、キャンペーン設定に記録。入場時に街を再建してアイテムを解放するが、使用可能な種類・残数は各ステージの`inventory`が決める。破損・容量不足を例外として検出するが、完全な復旧画面、バックアップ、複数端末同期、旧版からの移行、課金用のサーバー台帳は未実装。合成の10,000クリアデータは保存容量のテスト専用であり、候補盤面の正式採用や未検証盤面のクリアを表すものではない。
