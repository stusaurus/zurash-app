## 数学的検証

`node scripts/chapter-two-certify.js` で最短BFS・全手順再生・各必須アイテム除外・ゲート反実仮想を再計算する。時間またはノード上限は失敗（未検証）として扱う。58面では永久閉鎖ではなく再閉鎖停止禁止の正規ルール探索を要求する。60〜70面は全てゲート永久閉鎖で不可能。

65/70面はワープ残数1でも全状態探索して不可能。64面は氷、68面はワープ、70面は氷を禁止すると開扉もできない。

## 統合と保存

第1章50面・15修復・40星の会計・素材は維持。通常は50面クリアで第2章への導線が出る。第2章は独立したバージョン付き保存領域に合法手順と自己ベストを保存し、復元時にエンジンで再生する。次の面は前面クリアで解放。途中保存・Undo・リトライ・4段階ヒント・S/A/B・最短再挑戦に対応。家の星に未設計の報酬を加算しない。

自由試遊は明示的な別モード・別キー。好きな面へ直接入れるが通常冒険のクリア記録を増やさない。壊れた保存や未知バージョンは上書きせず、保存不可も画面で知らせる。

## CPUと家

CPU試作は既存 engine/ai の greedy 対戦を使い、先後入替公平性・人間試遊が未完のため必須ストーリーに組み込まない。個別特別イベントの研究ページを維持。

家の71ゲーム画像は再生成せず保持。既存の6シーン・15修復・装飾・保存復元・画像404検出・全50面通しはChapter one playthroughで検証する。生成元55PNGの旧環境からの回収はこの環境から確認できず、回収済みと報告しない。

## 一般公開までの優先順

1. iPhone実機での読みやすさ、誤タップ、難易度、54/57/59の面白さを評価し、採否を決定。
2. 公開用の初回ガイドと章の導入を仕上げる。第2章の結晶・4点灯・帰還・家の思い出は実装済み（expedition.md）。
3. 不公平性と対局テンポが確認できた場合のみCPUイベントを本編へ昇格。
4. 公開用タイトル・初回ガイド・クレジット・動作端末範囲を確認し、改めて本番公開を判断。

第71面以降は未制作。70面までの人間評価を確保する前に、類似面の追加や新ギミックの導入へ進まない。
