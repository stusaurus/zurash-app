# 長編ステージの最短手数・合格手数ポリシー（実験版）

現在の対象：`long-lab.html` の独立2面。`main`・正式50面・家の修復・セーブ・星報酬は変更しない。**人間の面白さ評価は未完了。**

## 確定できる数学的事実とできない評価
- 最短手数は `solo-v1` の**準備操作（任意の壁移動／アイテム）＋滑走**を1手と数え、完全幅優先探索（BFS）で求める。単なる例示解の長さを最短と呼ばない。
- `node scripts/challenge-certify.js` は全候補を新たに探索して `stage.challenge` と比較する。探索予算が尽きた場合・解けない場合・手数が食い違う場合は**失敗**とし、合格基準を発行しない。
- 新しい盤面の編集後は `node scripts/challenge-certify.js data/chapters/chapter-01/long-candidates-v1.json --write` で候補基準を再計算。その後 `npm test` と `npm run chapter:browser` を実行し、実機試遊で評価する。自動検証は「面白さ」を保証しない。
- ステージ1「氷の回廊」は最短16手、合格20手以内。ステージ2「星をめぐる迷宮」は最短19手、合格24手以内。画面には**合格手数だけ**を先に表示し、最短手数はクリア後に明かす。

## スコアリング（初期仮説）
| ランク | 条件 |
| --- | --- |
| S | 最短手数と一致 |
| A | 最短＋10%（切り上げ）まで |
| B（合格） | 最短＋25%（切り上げ）まで |
| 合格外 | 星は全取得できたが、合格手数を超えた |

- 合格手数を超えてもクリアは成立。やり直しを促しつつ次の候補を開く自由は残す（長編試遊版ではステージ選択が自由）。
- Undo・ヒント回数は**別記録**し、手数評価には混ぜない。取り組みやすさのためUndoに追加ペナルティは設けない。
- 自己ベストは開いているタブのメモリー上のみ。ブラウザ保存・家の星付与・サーバー送信なし。再読込で消える。
- 星の一括取得で合格手数判定。進行途中に合格枠を超えてもプレイ継続可能。

## 品質条件
1. データ内の `minimumTurns`・`aThrough`・`passThrough` がBFSの再計算と一致する。
2. 結果に表示する各ランクが、境界値・超過時まで単体テストで一致する。
3. Chromium / WebKit で全手順、結果画面、再挑戦、端末保存非干渉を検証する。
4. iPhoneで時間／タップ数／Undo／ヒント利用を試し、合格ラインが厳しすぎる場合は**盤面の難しさと基準を分けて**調整する。
5. ステージの頭脳的な難しさは、最短手数だけでなく分岐、壁の停止位置、手戻り、星の回収順、反復操作の少なさで評価する。

合格基準は本編への適用前に試遊結果から再検討する。Draft PR #7 は承認前の実験として維持する。
