# 第1章「氷の街に星あかりを」全50ステージ

2026年10月31日制作。解放時期を **10：アイスブロック／20：パワーグローブ／30：ワープクリスタル** に変更した。「10面までに3種を解放する」以前の提案は取り消す。

全50面の配置・最短手順・手順の再生・道具を除いた比較を保存した。クリア確認50面、未判定0面、解なし0面、回転・反転だけの重複0面。攻略手順の方向を揃えた分類は49種類（同じ分類は最大2面）。人間による面白さ・難度の試遊は未実施のため、Draftとして保存する。

## 遊ぶ入口

リポジトリをHTTPサーバーで配信し、`adventure.html`を開く。既存の`index.html`の対戦モードは変更していない。承認済みの氷の世界背景・ロゴ・トリケンを使用し、スマホとPCに対応する第1章用の独立した試遊画面を追加した。

```sh
python3 -m http.server 8080
# http://localhost:8080/adventure.html
```

基本は「壁を動かす準備を省略または1回→滑走を1回」。盤面の星は停止したマスで取得し、全取得でクリア。壁・移動先・方向の順に選ぶ。アイテムは壁移動の代わりに使用する。やり直し、1手戻す、ヒント、ステージ選択、初回報酬、街イベント、保存・復元を実装した。

## 解放・街づくり

|解放面|アイテム|街の発展|導入問題の実測|

各解放ステージに初めて入ったとき、初回クリアで集めた街の星を3個使って施設が完成し、そのステージからアイテムを使えるようにする。施設ごとの支出は一度だけ。再挑戦・再読込でも星を再び消費せず、解放状態も失わない。ステージを飛ばして入ることはできない。

解放状態と各面の使用残数は別管理。解放済みでも、その面の`inventory`で0なら使えない。表示にも「解放前」と「この面では使えません」を区別する。1〜9面はアイテム、氷ソケット、ポータル、固定障害物なし。最初から正方形・横長・縦長・L・切欠き・T・穴のある形を使い、星と動く壁の配置も変化させた。

章全体で盤面サイズは21通り。研究用の固定障害物は、11面以降では同じ停止効果を保った通行マスクの穴へ変換し、説明のない別の壁ギミックを増やしていない。

40〜50面の全11面では最短解に2種類以上のアイテムが現れる。50面の最短3手ではグローブ・氷・ワープの3種類を組み合わせる。別の長い解を禁止する手数制限は加えていない。アイテムを備えた全問題は、全アイテムを除くと最短手数が長くなるか、クリア不可になることも確認した。各アイテムが個別に必須とは限らない。

## 10,000面以降への拡張

- `data/campaign.json`に解放時期と章の索引を集約。解放条件を盤面エンジンへ埋め込まない。
- `data/chapters/chapter-01/chapter.json`に章の範囲・恒久ID一覧・前提条件を置く。第2章以降は前章クリアIDを`requires`へ指定できる。
- 表示順と恒久ステージIDを分離。第1章は`pz-100001`〜`pz-100050`を使い、研究候補のIDとは混在させない。
- SHA-256付きの10面単位チャンク5個をオンデマンド読込。既存の100面単位研究カタログもそのまま使える。画面は50枚を同時読込しない。
- アイテムの種類・回数、ソケット、ポータルは各ステージデータに保持。探索・再生・UIは同じルールを呼び出す。
- 進行の記録はキャンペーン単位。次章でもクリアID・街・解放を引き継げる構造。プレビュー保存は`zurash-app:chapter-preview:ice-town:v1`へ隔離し、本番用キー・2人戦・研究用セーブには書き込まない。
- ステージは`candidate`、章は`draft`を維持。明示的なプレビューだけが実行でき、標準の本番カタログ読込は候補を拒否する。

最初の50面をクリアすると街の星は計50個、施設に9個を使い、残高41個。再クリアによる報酬増殖は起きない。課金・クラウド同期・第2章の盤面・実機iPhoneの測定は今回の範囲に含めない。

## 自動検証と再現

```sh
npm test
npm run check
npm run chapter:verify
npm run puzzle:verify
# 同じ研究コーパスから章を再制作
npm run chapter:author
# Chromium/WebKit、320/390/1440pxで全50面を実際のボタンからプレイ
npm ci
npx playwright install --with-deps chromium webkit
npm run chapter:browser
```

`solutions.json`に50面の配置ハッシュ、最短手順、元の研究候補ID、道具なし比較を保存。`verification.json`は全50面を再探索・再生し、イベントと報酬を順番通りに実行した結果。単なる「解ありフラグ」を検査しているのではない。配置や効果を変えた場合は証拠を再生成する。

ブラウザのテストは全50面の実操作、10/20/30の街イベント、解放前の操作禁止、50面目でのアイテム使用後Undo、クリア報酬、再読込、同じ面の再クリア、横はみ出し、画像・スクリプト取得、ページ例外を確認する。画面のスクリーンショットと失敗時のtraceをCI成果物に保存する。

50面の自動クリア確認と、人間にとっての面白さ確認は別である。試遊で説明の過不足、タップのしやすさ、難度の上がり方、同じ感触が続かないかを調整する。現在の1万面対応可能性の結論を、50面の完成だけで上方修正していない。
