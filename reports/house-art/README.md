# 第5段階：外観と玄関の美術品質

PR #4 / `25de244ca3c232b5231305a5c16c608c38571079` を基点に制作。間取り、玄関、窓、部屋の入口座標とカメラ（480×540）は維持した。残る4シーンは従来モジュールのまま。

## 現状評価と変更

| 観点 | PR #4 | 今回の改善 |
| --- | --- | --- |
| 立体感・素材 | 平面の色と細い線が中心 | 木目・漆喰・石・シダーの素材、屋根瓦の重なり、面ごとの陰影 |
| 家の構造 | 南の扉、西の窓、東のキッチンと庭 | 同じ位置を維持。屋根下の透ける部分を壁で塞ぎ、室内側の取っ手を反転 |
| 雪と光 | 単色の山と木、青い窓 | 夕方の雪景色、雪の縁の青い影、氷柱、修復後の窓の琥珀色の光 |
| 玄関の小物 | 単純な図形のベンチ・服 | 木のベンチ、編み物、ブーツ、籠、コート、鍵の独立した透過素材 |
| トリケン | 70 / 77px | 正式画像は変更せず91 / 102pxへ。足元の影を追加 |
| 修復状態 | 亀裂・足場・色の変化 | 破損した板扉、冷たい光、床の傷、足場、完成後の素材と暖かな光 |
| 操作 | 常設カードに固定の入口が重なる | 通常はメニューを閉じ、部材タップで開く。パズル入口を通常フローに置き、重なりをなくす |

## レイヤー構成

- `src/house-art.js`：背景画像、素材定義、屋根・雪・小道・小物・照明の描画。
- `src/house-scenes.js`：従来の建物形状と修復状態を結び、扉・外壁・照明を別々に描く。修復IDと装飾番号0/1/2はそのまま。
- `src/house-view.js`：部屋への入口、44px以上の部材タップ領域、開閉式メニュー。状態や星の計算は行わない。
- `src/puzzle/house.js`：既存の保存・移行・修復会計。変更なし。

家を1枚の完成画像に置き換えていない。生成した雪景色には家・窓・家具を含めない。部材にマテリアルを貼り、照明と影を重ねる。コートやベンチの素材は修復対象ではない固定小物の透過レイヤーで、扉・壁・照明を覆わない。画像読込に失敗した場合も素材の下地色とSVG形状が残る。

## 比較と検証

`tests/fixtures/pr4-house-scenes.js` はPR #4の描画の保存コピー（import先のみテスト用に変更）。`house-art-review.html` は保存や星を変更しない比較専用ページ。新旧とも同じ390px、同じカメラ、同じ修復・デザインデータで撮影する。修復前、完成後3種、今回の建設中を比較する。テストfixtureを正式ステージや製品データに採用しない。

70単体テストと50面の探索・証明再生は成功。ブラウザで新旧の美術と部材タップによるメニュー表示を確認した。Chromium / WebKit の操作・比較と320 / 390 / 1440pxの通し検証は実行後に追記する。

iPhone実機での直接検証は未実施。HTTPの内部プレビューでは既存Web Cryptoの整合性検査が使えないため、実際の攻略試験はlocalhostのCIで行い、試遊にはHTTPSの独立URLを使う。
